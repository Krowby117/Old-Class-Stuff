#### 3. Evaluate the pros and cons of at least four agile practices that Extreme Programming introduced into mainstream software development culture

***Refactoring*** - It can keep the code simple and maintanable but if too much time is spent improving the same code then it can be harder to find time for implementation.

***On-site Customer*** - Can provide instnat feedback for new systems and features, but may not be super accurate to actual users since they are part of the team

***Pair Programming*** - Provides support and help for any tasks, but if the pair disagrees its not great.

***Continuous Integration*** - Keeps the main systems codebase up to date but can may inadvertantly slow down production if a task has errors or multiple new tasks interfere with eachother

#### 4. Differentiate the related terms “Agile”, “XP”, and “Scrum” with regards to the role each plays in software development 

***Agile*** - A faster software development technique that were designed to produce useful software quickly. All Agile methods proposed share a number of common ideas. Overarching "umbrella" term.
 - Specification, designm and implementation are lessened. No detailed specifications or design documentation, mianly just the most important bits.
 - Systems are developed in increments based off of user and stakeholder feedback
 - Extensive tool support is used

***XP*** - An Agile methodology focused on technical excellence and engineering practices. Focus on how code is written and maintained.

***Scrum*** - An Agile framework for managing work and teams. Focus on how teams organize and share their code, less focus on how its written.

## General Notes:
***Software Process*** - A set of related activities that leads to the production of a software system

***Plan-driven Processes*** - Processes where all of the process activities are planned in advance and progress is compared to the plan

***Agile Processes*** - Process where planning is incremental and continual as the software developed

***SDLC Model*** - *Software Development Livecycle* A simplified representation of a software process, each process model represents a process from a particular perspective and only provides partial info

Large systems generally want a balance between a plan-driven and an agile process
